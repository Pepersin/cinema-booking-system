# Требования к системе бронирования билетов в кинотеатр

**Тип работы:** учебная проектная документация по дисциплине «Программная инженерия», НГТУ, 2025 г.  
**Основа:** лабораторные работы по анализу предметной области и требованиям, документ «Спецификация требований к программному обеспечению».  
**Статус:** проектируемая система. Требования описывают ожидаемое поведение продукта; не все функции реализованы в учебном веб-прототипе.

## 1. Назначение и цели

Система предназначена для поиска киносеансов, выбора мест и оформления заявок на бронирование билетов через веб-интерфейс, а также для работы кинотеатров с расписанием и поступившими заявками.

Бизнес-цели, сформулированные в учебной работе:

- Упростить доступ зрителей к актуальному расписанию и сведениям о фильмах.
- Сделать процесс бронирования удобнее и снизить нагрузку на кассы.
- Предоставить кинотеатрам инструмент для управления сеансами и обращениями пользователей.
- Создать основу для дальнейшего расширения платформы.

## 2. Роли пользователей

| Роль | Основные действия |
| --- | --- |
| Зритель | Поиск и просмотр фильмов, добавление в избранное, выбор сеанса и мест, оформление бронирования, просмотр статуса заявки. |
| Кинотеатр / партнёр | Регистрация, создание и редактирование карточек фильмов и сеансов, управление расписанием и обработка заявок. |
| Администратор / модератор | Проверка карточек перед публикацией, управление контентом и отзывами. |

## 3. Функциональные требования

Ниже требования из учебной спецификации объединены по ролям. Идентификаторы добавлены для удобства навигации по документу.

| ID | Роль | Требование |
| --- | --- | --- |
| FR-01 | Зритель | Система должна поддерживать поиск фильмов по названию, жанру, актёрам, дате выхода и времени сеанса. |
| FR-02 | Зритель | Пользователь должен иметь возможность добавлять фильмы в избранное и удалять их из избранного. |
| FR-03 | Зритель | Система должна предоставлять выбор фильма, даты, времени и мест в зале при оформлении бронирования. |
| FR-04 | Зритель | Пользователь должен иметь возможность просматривать историю бронирований и статусы заявок. |
| FR-05 | Кинотеатр | Система должна позволять кинотеатру создавать учётную запись с данными о заведении. |
| FR-06 | Кинотеатр | Представитель кинотеатра должен иметь возможность добавлять карточки фильмов с описанием, жанром, постером и расписанием. |
| FR-07 | Кинотеатр | Представитель кинотеатра должен иметь возможность изменять статус заявки. |
| FR-08 | Администратор | Перед публикацией карточка фильма должна проходить проверку. |
| FR-09 | Администратор | Система должна предоставлять функции редактирования, архивации и удаления карточек, отзывов и обращений. |
| FR-10 | Администратор | Система должна позволять проверять отзывы пользователей перед публикацией. |

## 4. Нефункциональные требования и проектные ограничения

Все показатели ниже являются **заданными в учебной работе требованиями**, а не результатами испытаний готовой системы.

| Область | Требование / ограничение |
| --- | --- |
| Производительность | Основные страницы должны загружаться менее чем за 3 секунды. |
| Нагрузка | Предусмотрена поддержка до 50 одновременных пользователей. |
| Доступность | Круглосуточный доступ, за исключением технического обслуживания; предусмотрен автоматический перезапуск сервера после сбоя. |
| Безопасность | Аутентификация для защищённых функций; безопасное хранение паролей (в исходном документе приведён bcrypt как пример). |
| Совместимость | Google Chrome, Яндекс Браузер, Microsoft Edge, Mozilla Firefox. |
| Интерфейс | Единый визуальный стиль; поддержка светлой и тёмной темы. |
| Сопровождение | Логирование ошибок, обращений и действий пользователей; возможность обновления и расширения функциональности. |
| Предлагаемая архитектура | Django (Python), React (JavaScript), PostgreSQL; Docker рассматривается как возможный вариант развёртывания. |

**Примечание по реализации:** указанный технологический стек — проектное решение из документации. Отдельный учебный прототип в архиве разработан на Flask с JSON-хранилищем и не является полной реализацией этой архитектуры.

## 5. Границы первой версии (MVP)

В учебной спецификации к первой версии относятся:

- Каталог фильмов и сеансов, карточки и поиск с фильтрами.
- Избранное, выбор мест, создание заявок на бронирование.
- Кабинет кинотеатра для работы с контентом, расписанием и заявками.
- Модерация контента.

В первую версию **не входят** полноценные мобильные приложения для iOS/Android, онлайн-оплата и биллинг, полноценная CRM кинотеатров и сложная система рекомендаций. Для мобильных устройств предлагается веб-версия (PWA).

## 6. Проектные KPI

В учебном документе заявлены следующие ориентиры, ещё не подтверждённые измерениями:

| Показатель | Целевое значение |
| --- | --- |
| Поиск подходящего фильма или сеанса | Не менее 75% пользователей находят результат за 2 минуты. |
| Переход от просмотра карточки к бронированию | Не менее 20%. |
| Обработка заявки кинотеатром | В течение 12 часов. |
| Полнота карточек фильмов и сеансов | Не менее 95%. |
| Доступность платформы | Не менее 98% времени (KPI из спецификации). |

## 7. Вопросы для дальнейшего уточнения

- Определить правила блокировки мест и предотвращения повторного бронирования одного места.
- Согласовать точные статусы заявки и допустимые переходы между ними.
- Уточнить сценарии ошибок при оформлении бронирования и отмене заявки.
- Согласовать показатель доступности: в разных учебных материалах он сформулирован по-разному.
- Сопоставить каждый пункт с фактическими функциями прототипа перед утверждением, что требование реализовано.

Этот документ описывает **проектные требования** и не является отчётом о тестировании или подтверждением реализации всех функций.
